The Idea

Read this before you build. Four minutes.

Theory 01

Why One Agent Underperforms

Ask one agent to research, analyse, write and check, and it silently trades quality between them. Each stage deserves its own instruction, its own constraints, and its own definition of done.

Theory 02

The Handoff Is the Hard Part

Pipelines rarely fail inside a stage. They fail in the gap between two stages, because nobody defined what crosses it.

Your Pipeline

Three stages, three specialists. Here's your exact split.

◈ HR Scouting Exec

Screening a candidate well means sourcing evidence, judging it against a standard, and writing it up. One agent doing all three does none properly.

Stage 1

Evidence Extractor

Role: extract only. Pull every factual claim — employers, dates, titles, technologies, scope, outcomes. Make no judgement.
Output: table of claim | source line | confidence (stated / implied / absent).
Stop: if the profile is unreadable or under 100 words, return INSUFFICIENT INPUT and stop.
Stage 2

Scorecard Assessor

Role: judge only. Map each scorecard requirement to the evidence supporting it.
Input rule: accepts only stage 1's table. If confidence is 'implied', treat it as unevidenced.
Stop: if more than half the must-haves are Not Evidenced, return NO with reasons — do not proceed to write-up.
Stage 3

Hiring Manager Brief

Role: communicate only. Turn stage 2 into a 90-second read.
Output: verdict, two decisive factors, three probing questions aimed at Partial items, open risks.
Constraint: may not introduce any claim absent from stage 1's table.
The part people miss
Stage 2's stop condition saves the most time. Killing a clear No before write-up is the entire point of a pipeline.

◉ Content & Social

A good content brief needs scanning, angle-finding, and drafting. Merge them and the draft quietly reshapes the research to fit itself.

Stage 1

Signal Scanner

Role: gather only. Collect what is actually being observed on the platforms in scope.
Output: signal | platform | date observed | source | strength (strong / emerging / weak).
Stop: if fewer than three sourced signals exist, return THIN EVIDENCE and stop.
Stage 2

Angle Generator

Role: interpret only. Produce content angles our audience would care about.
Input rule: may only build angles on strong or emerging signals. Weak may be listed, never built on.
Constraint: no drafting. Angles only.
Stage 3

Drafter

Role: write only. Draft one selected angle to the platform rules in the knowledge base.
Input rule: accepts exactly one angle plus its supporting signals.
Constraint: may not add a claim not present in the supporting signals. Must pass the banned-language check.
The part people miss
Stage 3's rule against adding claims is what stops the draft from inventing a statistic to make the hook land better.

▣ Project Manager

A status update needs collection, analysis, and communication. Do them together and the narrative starts editing the facts.

Stage 1

Activity Collector

Role: collect only. Pull the period's activity per workstream from the connected tracker.
Output: workstream | items completed | items slipped | new blockers | last activity date.
Stop: any workstream with no activity is marked NO SIGNAL and listed separately — never omitted.
Stage 2

Risk Analyst

Role: analyse only. Apply the RAG thresholds from the knowledge base.
Input rule: accepts only stage 1's table. May not gather new information.
Stop: if a RAG cannot be set from available data, return NEEDS INPUT naming the missing field.
Stage 3

Sponsor Briefer

Role: communicate only. Turn stage 2 into the sponsor-facing update.
Constraint: may not change any RAG set by stage 2.
Constraint: must isolate the single sponsor-actionable item. Maximum 200 words.
The part people miss
Stage 3 being forbidden from changing a RAG is the governance move. It separates who judges from who presents.

Map before you build12 MIN

Goal: the pipeline on paper. Building before mapping is the classic mistake.

Do this now
  1. Write your workflow as a single sentence, then underline every distinct verb.
  2. Each underlined verb is a candidate stage. Merge any two that always happen together.
  3. For each gap between stages, write the handoff: exactly what crosses, in what structure.
◈ Your split: Extract → Assess → Brief.
◉ Your split: Scan → Angle → Draft.
▣ Your split: Collect → Analyse → Brief.
✓ You know it worked when: three stages on paper, with the handoff structure written for each gap.
2

Build stage one15 MIN

Goal: the gathering stage. Make it refuse to judge.

Do this now
  1. Create the first specialist with an RCTFX prompt. Its ROLE must be a gatherer.
  2. Add the explicit line: "Make no judgement and draw no conclusion. Extraction only."
  3. Define the output contract as a table with named columns.
  4. Add the stop condition — what makes it refuse to continue.
◈ It must NOT decide fit. Only what the profile claims, and where.
◉ It must NOT choose angles. Only what was observed, where, and when.
▣ It must NOT set RAG. Only what happened per workstream.
✓ You know it worked when: you ran it on real input and it returned structured data and zero opinions.
3

Build stage two and wire the handoff18 MIN

Goal: the judgement stage, accepting only stage one's structure.

Do this now
  1. Create the second specialist. Its first instruction is the input requirement: it only accepts stage one's table format.
  2. Add the rule for missing fields — explicitly. Never leave it to inference.
  3. Add its own stop condition.
  4. Paste stage one's real output into it and run.
◈ Your rule: 'implied' confidence counts as unevidenced. State it explicitly.
◉ Your rule: only strong and emerging signals may support an angle.
▣ Your rule: RAG comes only from the documented thresholds.
If you had to hand-fix the format, the contract is incomplete. That's the lesson.
✓ You know it worked when: stage two ran on stage one's real output without you reformatting anything by hand.
4

Build stage three and run end to end18 MIN

Goal: the full pipeline, on real input, once through.

Do this now
  1. Create the communication stage. Its defining constraint is what it may NOT do — introduce new claims, or change a prior judgement.
  2. Run the whole chain from real raw input to final output.
  3. Trace one sentence in the final output all the way back to the raw input. If you can't, a handoff is leaking.
◈ Trace test: trace one line of the hiring brief back to a line in the CV.
◉ Trace test: trace one claim in the draft back to a sourced signal.
▣ Trace test: trace the RAG in the sponsor update back to a threshold and an activity record.
This trace is your proof of governance. It's what makes the system auditable.
✓ You know it worked when: one complete run, and you traced a final sentence back to raw input.
5

Break it on purpose12 MIN

Goal: find the failure point now instead of in production.

Do this now
  1. Feed stage one deliberately incomplete input. Does its stop condition fire, or does it improvise?
  2. Feed stage two a malformed handoff. Does it reject it, or does it guess the structure?
  3. Whichever stage improvised is your weakest link. Tighten its input requirement and re-test.
◈ Try: a two-line profile. It should return INSUFFICIENT INPUT.
◉ Try: one weak unsourced signal. It should return THIN EVIDENCE.
▣ Try: a period with two silent workstreams. Both should appear as NO SIGNAL.
✓ You know it worked when: you know which stage fails first and you have tightened it once.

When It Doesn't Work

Every one of these has a cause you can name and a fix you can apply in under two minutes.

SymptomActual causeThe fix
Stage two reinterprets stage one No input requirement, so it treats the handoff as a loose suggestion. Make the first line of stage two the input contract, with named fields it will refuse without.
Final output contains claims from nowhere The last stage is allowed to add material. Add: "may not introduce any claim not present in the input." Then re-run the trace test.
The pipeline is slower than doing it manually Too many stages for the size of the job. Merge any two stages that never vary independently. Three is usually the ceiling for this work.
