WHERE THIS SITS

You Are Adding Layer 4

You cannot skip a layer. A pipeline with no knowledge layer is three agents guessing instead of one.

THE PROBLEM

Why One Agent Underperforms

Ask one agent to research, analyse, write and check — and it silently trades quality between them.

THE MONOLITH
"Review this CV against the job spec, assess the candidate, and write me a summary for the hiring manager."
WHAT ACTUALLY HAPPENS

✗ Evidence and opinion blur together
✗ It "reads" a claim that was never there
✗ The summary shapes the assessment
✗ You can't audit which step went wrong
✗ It always answers — even on a blank CV

Each stage deserves its own instruction, its own constraints, and its own definition of done.

THE MENTAL MODEL

Three Ways to Split a Job

PATTERN 01 · TODAY

Pipeline

Each stage's output feeds the next. Best when the work has a natural order — which yours does.

PATTERN 02 · LEVEL UP

Supervisor

A coordinator delegates and assembles. The 2026 default for anything non-linear. Try it if you finish early.

PATTERN 03 · HIGH STAKES

Debate

Two agents argue opposite positions, a third adjudicates. Expensive — but excellent for high-stakes judgement calls.

Rule of thumb: three stages is the ceiling for this kind of work. Merge any two that never vary independently.

THE CRITICAL CONCEPT

The Handoff Is the Hard Part

Pipelines rarely fail inside a stage. They fail in the gap between two stages.

A pipeline that always produces output will happily produce confident garbage.

THE TEMPLATE

Anatomy of a Pipeline Stage

RCTFX from Session 2, plus the two fields that make it a stage instead of a prompt.

INPUT REQUIREMENT ← NEW. Gate on the way in. This agent accepts ONLY [STRUCTURE]. If input is not in that form, return MALFORMED INPUT and stop. ROLE Act as a [SPECIFIC EXPERT] who [DOES ONE THING]. CONTEXT [WHAT IT CANNOT SEE — brand, standard, history] TASK [ONE VERB] the [ONE DELIVERABLE]. FORMAT Output contract: a table with columns [COL1] | [COL2] | [COL3]. CONSTRAINTS Never [THE THING THIS STAGE MUST NOT DO]. STOP CONDITION ← NEW. Gate on the way out. If [FAILURE CASE], return [FLAG] and stop.
THE TWO NEW FIELDS

Input requirement

Stops this stage accepting a sloppy handoff. Without it, the stage guesses the structure and quietly re-interprets everything upstream.

Stop condition

Stops this stage producing output it cannot justify. Without it, a blank input still yields a confident answer.

THE ONE-VERB TEST

Read your stage's TASK out loud. If it contains "and", you have two stages, not one.

✗ "Extract the claims and score them" ✓ "Extract the claims" → stage 1 ✓ "Score the claims" → stage 2
Where this goes → you will paste this exact block into the Set project instructions field of one Claude Project per stage. Next slide shows you precisely where.

PICK YOURS

Your Pipeline, Mapped

Screening a candidate well means sourcing evidence, judging it against a standard, and writing it up. One agent doing all three does none properly.

STAGE 1 · GATHER

Evidence Extractor

Does: pulls every factual claim — employers, dates, titles, tech, scope, outcomes.

Never: judges fit.

Stops if: profile <100 words → INSUFFICIENT INPUT

STAGE 2 · JUDGE

Scorecard Assessor

Does: maps each requirement to the evidence supporting it.

Never: gathers anything new.

Stops if: >half must-haves unevidenced → NO

STAGE 3 · COMMUNICATE

Hiring Manager Brief

Does: turns the assessment into a 90-second read.

Never: introduces a claim absent from stage 1.

Key: verdict + 2 factors + 3 questions + risks

The part people miss: stage 2's stop condition saves the most time. Killing a clear No before write-up is the entire point of a pipeline.

A good content brief needs scanning, angle-finding, and drafting. Merge them and the draft quietly reshapes the research to fit itself.

STAGE 1 · GATHER

Signal Scanner

Does: collects what is actually being observed on the platforms in scope.

Never: chooses angles.

Stops if: <3 sourced signals → THIN EVIDENCE

STAGE 2 · JUDGE

Angle Generator

Does: turns signals into angles the audience would care about.

Never: drafts. Angles only.

Rule: only strong/emerging signals may support an angle

STAGE 3 · COMMUNICATE

Drafter

Does: drafts one selected angle to the platform rules.

Never: adds a claim not in the signals.

Key: must pass banned-language check

The part people miss: stage 3's rule against adding claims is what stops the draft inventing a statistic to make the hook land better.

A status update needs collection, analysis, and communication. Do them together and the narrative starts editing the facts.

STAGE 1 · GATHER

Activity Collector

Does: pulls the period's activity per workstream from the tracker.

Never: sets RAG.

Stops if: silent workstream → NO SIGNAL, listed separately

STAGE 2 · JUDGE

Risk Analyst

Does: applies the documented RAG thresholds to stage 1's data.

Never: gathers new information.

Stops if: RAG unsettable → NEEDS INPUT + missing field

STAGE 3 · COMMUNICATE

Sponsor Briefer

Does: writes the sponsor-facing update, max 200 words.

Never: changes a RAG set by stage 2.

Key: isolate the one sponsor-actionable item

The part people miss: stage 3 being forbidden from changing a RAG is the governance move. It separates who judges from who presents.

STEP 1 OF 5  ·  12 MINUTES  ·  NO TOOLS YET

Map Before You Build

Building before mapping is the classic mistake. Paper first.

1
Write your workflow as one sentence.
"I read the CV, check it against the scorecard, and write a summary for the hiring manager."
2
Underline every distinct verb.
read · check · write — three verbs, three candidate stages.
3
Merge any two verbs that always happen together.
If you never do one without the other, they are one stage.
4
For each gap, write what crosses it — in what structure.
Not "the findings". Named columns: claim | source line | confidence.
✓ Done when: three stages on paper, and a written handoff structure for each gap.
💡 Say the handoff out loud. If you can't say the column names, you haven't defined it.
FILL THIS IN
— MY WORKFLOW — I ______ the ______, then ______ it against ______, then ______ a ______ for ______. — MY THREE STAGES — STAGE 1: ____________ (verb: gather) STAGE 2: ____________ (verb: judge) STAGE 3: ____________ (verb: communicate) — HANDOFF 1 → 2 — Structure: a table with columns ______ | ______ | ______ — HANDOFF 2 → 3 — Structure: a table with columns ______ | ______ | ______
⚠ If a stage name contains "and", split it. That's two stages wearing one coat.

STEP 3 OF 5  ·  18 MINUTES

Build Stage 2 and Wire the Handoff

The judgement stage — which accepts only stage one's structure.

1
New project: "S2 · [your judge stage]".
2
Make the input requirement the very first line.
Before ROLE. Before everything. It's a gate, not a footnote.
3
Attach your S3 knowledge base here.
This is the stage that needs your standard — scorecards, RAG thresholds, banned language.
4
State the missing-field rule explicitly.
Undefined missing-field behaviour is exactly where pipelines invent data.
5
Copy stage 1's real output. Paste into stage 2. Run.
Real output — not a tidied-up version. The mess is the test.
⚠ If you had to hand-fix the format to make it work, your contract is incomplete. Go back and add the missing column to stage 1's FORMAT block. This is the lesson, not a failure.
✓ Done when: stage 2 ran on stage 1's raw output with zero manual reformatting.
INPUT REQUIREMENT — READ FIRST This agent accepts ONLY a markdown table whose first row is the column names: claim | source line | confidence If the input is not in that exact structure, return exactly: MALFORMED INPUT — expected columns: claim | source line | confidence and stop. Do not guess the structure. Do not repair it. ROLE Act as a [DOMAIN] assessor applying [THE STANDARD]. TASK Map each requirement in [THE STANDARD] to the evidence supporting it in the input table. MISSING FIELD RULE If a claim's confidence is 'implied' or 'absent', treat it as UNEVIDENCED. Never infer, never upgrade, never fill a gap. FORMAT — OUTPUT CONTRACT Table. Columns: requirement | evidence ref | verdict verdict is one of: Evidenced / Partial / Not Evidenced CONSTRAINTS - Gather nothing new. Judge only what the table contains. - Every verdict must cite an evidence ref from the input. STOP CONDITION If more than half of the must-haves are Not Evidenced, return: NO — [reasons] and stop. Do not proceed to any write-up.
STEP 3  ·  THE MOMENT THAT MATTERS

Test the Gate — Twice

TEST 1 · THE GOOD HANDOFF

Paste stage 1's real output, unedited.

claim | source line | confidence Led platform rewrite | L12 | stated Managed 4 engineers | L18 | stated Comfortable ambiguity | L24 | implied
Expected: a clean verdict table, with "Comfortable ambiguity" treated as unevidenced.
TEST 2 · THE BROKEN HANDOFF

Now paste something deliberately malformed.

// no header row, wrong columns Led platform rewrite, seems strong Managed 4 engineers — good sign Probably handles ambiguity well
Expected: MALFORMED INPUT and a full stop.

If it answered anyway — your input requirement is too soft. Move it to line one and make it literal.

The whole point: an agent that refuses bad input is worth ten that always produce something.

STEP 4 OF 5  ·  18 MINUTES

Stage 3 and the Full Run

The communication stage — defined entirely by its prohibitions.

1
New project: "S3 · [your communicate stage]".
2
Lead with what it may NOT do.
No new claims. No changing an upstream verdict. This is the governance move.
3
Run the whole chain: raw input → S1 → S2 → S3.
Copy-paste between projects is fine. Automating the handoff is Session 5.
4
Do the trace test — pick one sentence in the final output and walk it all the way back.
💡 If you can't trace it, a handoff is leaking. Find which stage introduced the untraceable claim — that stage is missing a constraint.
✓ Done when: one complete run, and you traced a final sentence back to raw input.
HARD CONSTRAINTS — THESE OVERRIDE EVERYTHING - You may NOT introduce any claim not present in the input. - You may NOT change any verdict or rating set upstream. - If you cannot say something without inventing it, omit it. ROLE Act as a [DOMAIN] communicator writing for [AUDIENCE], who reads on a phone and will act on exactly one thing. TASK Turn the assessment below into a [90-SECOND READ]. FORMAT — OUTPUT CONTRACT 1. Verdict, one line, with the reason. 2. The two decisive factors. 3. Three questions probing the weakest items. 4. Open risks. Maximum [N] words. PROVENANCE After each substantive claim, cite the evidence ref it came from, in square brackets. e.g. [ref: claim #7] INPUT: [PASTE STAGE 2 OUTPUT]
THE TRACE TEST
Final brief says: "shipped without a spec twice" ↓ Stage 2 row: autonomy | claim #7 | Evidenced ↓ Stage 1 claim #7: "led greenfield rewrite, self-directed" — CV line 12 ✓ TRACED
STEP 5 OF 5  ·  12 MINUTES

Break It On Purpose

Find the failure point now, in a room full of people who can help.

ATTACK 1 · STARVE IT

Feed stage 1 almost nothing

A two-line profile. One unsourced signal. A period with no activity.

PASS → INSUFFICIENT INPUT FAIL → it invents a plausible history
ATTACK 2 · MALFORM IT

Feed stage 2 a broken handoff

Wrong columns, no header row, prose instead of a table.

PASS → MALFORMED INPUT FAIL → it guesses the structure anyway
ATTACK 3 · TEMPT IT

Ask stage 3 for something absent

"Add their salary expectation" / "Add the engagement rate."

PASS → says it isn't in the input FAIL → invents a number
THEN DO THIS

Whichever stage improvised is your weakest link. Tighten its input requirement or stop condition — one change only — and re-run the same attack. Change one thing, re-test. That loop is the whole skill.

✓ Done when: you know which stage fails first, and you have tightened it once.
WHEN IT DOESN'T WORK

Three Things That Go Wrong

Each has a nameable cause and a fix you can apply in under two minutes.

SYMPTOM

Stage 2 reinterprets stage 1

ACTUAL CAUSE

No input requirement, so it treats the handoff as a loose suggestion.

THE FIX

Make the first line of stage 2 the input contract, with named fields it will refuse without.

SYMPTOM

Final output has claims from nowhere

ACTUAL CAUSE

The last stage is allowed to add material.

THE FIX

Add "may not introduce any claim not present in the input" — then re-run the trace test.

SYMPTOM

Slower than doing it manually

ACTUAL CAUSE

Too many stages for the size of the job.

THE FIX

Merge any two stages that never vary independently. Three is the ceiling for this work.
